# План адаптации и типографики (v2)

> v2 фиксирует решения из обсуждения: перевод на `rem`, модель **Reflow (снизу) + Zoom (сверху)**, `clamp()` только в мобильно-планшетной зоне, типографические токены-роли. Раздел «Фирменная логика скруглений» — инвариант, не меняется.

---

## 0. Принятые архитектурные решения (контракт)

**0.1. Перевод всего проекта на `rem`.**
Шрифты, отступы (`padding`, `gap`, `margin`), физические размеры блоков (карточки, триггеры, медиа, высоты) — в `rem` (базовый `1rem` = размер шрифта корня). В `px` остаётся только то, что перечислено в 0.4.

**0.2. Reflow снизу, Zoom сверху.**
- **Снизу (`≤1280px`) — Reflow:** смена раскладок/структуры через `@media (в px)`.
- **База `1281–1499px`:** desktop-раскладка, масштаб `1×`.
- **Сверху (Zoom) — на крупных тирах:** `≥1500px` ×1.08, `≥1850px` ×1.3 — **исключительно** через `html { font-size }`. Раскладка не меняется, весь макет (текст + блоки) пропорционально растёт. *(Значения — из текущего кода `--type-scale`, style.css:990/997; план ранее писал ×1.4 — устарело.)*
- `transform: scale()` для layout **запрещён** (мылит растр, ломает позиционирование/скругления/анимации).

> ⚠️ **Расхождение с черновиком:** в черновике «Zoom с 1280px». Точнее — между 1280 и 1500 идёт обычная desktop-раскладка `1×`, а сам zoom стартует на крупных тирах `1500/1850`. Иначе «прыжок» на 1280 сломает 1440.

**0.3. `clamp()` — только в нижней зоне (`≤1280px`).**
Плавность шрифтов/текста на мобильных и планшетах. Выше 1280 `clamp` для **масштаба** не используется — иначе он перемножается с изменением корня (двойное масштабирование, см. 0.6).

> ⚠️ **Уточнение к черновику:** «clamp отключается выше 1280» — правило для **масштабных** значений. Остаются легаси-исключения: защитная полоса `.hero-title` `(min-width:1025px) and (max-width:1499px)` и `geo-map height`. Их разбираем при миграции (см. §5.3).

**0.4. Что остаётся в `px` (не масштабируется).**
- Бордюры/разделители/хайрлайны `1px`.
- **Брейкпоинты в `@media`** — всегда `px` (в `@media` единицы `rem`/`em` считаются от начального 16px, а **не** от `html font-size` → не следуют за zoom).
- Значения, привязанные к вьюпорту: `vh`/`vw` (напр. высота вертикальной линии), `ch`-ограничения длины строк.

**0.5. a11y корневого шрифта.**
`html { font-size }` задаётся **от пользовательского дефолта**, а не фиксированным `px`: `calc(100% * k)`. Так масштаб умножает пользовательскую настройку размера шрифта и не ломает доступность. Задавать `html { font-size: 16px }` — нельзя.

**0.6. Один уровень флюида.**
Масштабом рулит **либо** корень, **либо** `clamp` на элементах — не оба на одном свойстве. На нижней зоне — `clamp`; на крупных тирах — корень.

**0.7. Анимация.**
Координаты анимаций — в той же системе единиц (`rem`), либо считаются от **фактической геометрии** элемента/контейнера (`getBoundingClientRect`), а не от хардкода пикселей под конкретную ширину. Тогда zoom безопасен и анимация «встаёт» на всех тирах.

**0.8. Типографические токены-роли.**
Ограниченный набор ролей (`--fs-h1 … --fs-label`) в `rem` — единый источник правды; все элементы маппятся на роли. **Одна роль = один класс** (см. §5.3.4).

## 1. Как сейчас реализована адаптация (факты)

**Подход:** desktop-first, почти все правила — `@media (max-width: …)`. Тир для больших экранов сейчас присутствует частично (переходный `--type-scale` на `≥1500/≥1850`).

**Брейкпоинты унифицированы** до набора `480 / 600 / 768 / 1024 / 1280 / 1500 / 1850` (см. §5.2 — ВЫПОЛНЕНО).

**Контейнеры:** `--container-max: 1200px` (в `rem` пока нет); `.calc-container` берёт его из токена; у `.hero-section` — `max-width: calc(var(--container-max) + 2 * var(--gutter))` (**hero уже зажат в контейнер**, §5.1 выполнен). Внутренние ограничения (`820px`, `600px`, `60ch`) — не трогать.

**Сетки:** CSS Grid + Flexbox — плюс, сохраняем.

**Типографика:** фиксированные `px` + множитель `--type-scale` (масштабировал **только шрифты** → отсюда «кривой» zoom). `clamp` — точечно (hero-h1, футер, `geo-map height`, один B2B-текст).

**Уже сделано:** семантические заголовки приведены к системе **H1 `.hero-title` / H2 `.section-title` / H3 `.section-subtitle` / H4 `.card-title`** (убраны локальные `.calc-title`/`.why-we-title`).

**Прочее:** `rem` = 16px (`html` font-size не задан); `box-sizing` глобальный; `:root` с токенами/темами; 1 container query; `viewport meta` корректная.

## 2. Проблемы именно для 1920×1080

1. Выше ~1400px вёрстка «растягивается», а не масштабируется — нет верхней границы у hero.
2. Рассогласование: hero во всю ширь, остальное в 1200px → разный ритм; вертикальная линия 58.33% уходит от контента.
3. `--type-scale` масштабировал только шрифты → блоки и анимации разъезжались.
4. До унификации не было единой системы брейкпоинтов.

## 3. Целевая модель (сводно)

- **Единый контейнер** для всех секций (в т.ч. hero).
- **Единый набор брейкпоинтов** (готов).
- **Reflow снизу / Zoom сверху** (0.2).
- **Токены-роли типографики** в `rem` (0.8).
- **Fluid-отступы секций** через `clamp()` (нижняя зона).
- **Ограничение длины строк** абзацев (`~65–75ch`) на широких экранах.
- **Вертикальный разделитель** привязан к контейнеру.

## 4. Фирменная логика скруглений при перекомпоновке (инвариант — не ломать)

> «Сохранить фирменную логику скругления углов при перекомпоновке объектов для разных разрешений: когда в стопку — меняются углы для скругления.» — Alex

**Суть паттерна.** Объекты, стоящие встык (тонкий стык 3px или общая рамка), читаются как **единый блок**. Скругляются только **внешние** углы группы (те, что граничат с фоном секции), внутренние стыки — **прямые**. Когда раскладка меняется (ряд → стопка, другая сетка), «внешними» становятся другие углы, и вёрстка **пересчитывает** скругления под новую геометрию. В каждом брейкпоинте перекомпоновки углы сначала **обнуляются** (`border-radius: 0`), затем назначаются заново — иначе правила прошлого тира наследуются каскадом.

**Где реализовано (карта для регресса):**

| Компонент | Раскладки и как меняются углы | Строки |
|---|---|---|
| Каталог `.pest-card` / `.pest-grid` | десктоп 6×1 (левый край первой, правый последней) → планшет 3×2 (4 внешних угла верх./ниж. ряда) → моб. 3 колонки; обнуление в каждом тире | 1840–1954 |
| Прайс `.price-card` / `.prices-grid` | 3×1, только внешние углы; логика снимается ≤1024 | 1143–1157 |
| Калькулятор `.v2-prices` / `.v2-calc` | пара карточек, внешние углы только ≥1025 | 1420–1430 |
| «Почему мы» `.why-we-step` / `.why-we-mark` | слитное поле; заливка-маркер зеркалит нижний правый угол (`border-bottom-right-radius`) | 2024–2049 |
| «Почему мы» `.why-we-card` | 2×2 → 1×4 (верх первой / низ последней) | 2338–2355 |
| Note-блок `.why-we-note-text` / `.why-we-note-actions` / `.why-we-note-tg` | в ряд: `12px 0 0 12px` + `0 0.75rem 0.75rem 0` + скос на tg `::before` → в колонку: текст `12px 12px 0 0`, монолит `0 0 12px 12px`, tg без скоса | 2198, 2214, 2253, 2301–2325 |
| B2B `.b2b-tag` / `.b2b-tags` | 2×3 (4 внешних угла) → в колонку (верх/низ) | 2497–2510, 2645–2669 |
| CTA hero `.cta-deal` / `.cta-discount` | слитная плашка; красный бейдж зеркалит угол и перекрывает рамку через negative-margin | 726, 747–749 |
| Hero-фото `.image-container-block` | асимметричное скругление `--radius-asym: 2rem 0.5rem 2rem 2rem` | 76, 628 |
| Отзывы `.review-card` / `.reviews-track` | внешние края ленты; управляются JS-классами `.is-edge-start/end` (до инициализации — `:first/last-child`) | 2986–3006 |
| Футер `.footer-grid` | внешние углы первого/последнего столбца; пересчёт в тирах | 1812–1849, 1934–1952 |

**Инварианты при адаптации под 1920 и рефакторинге:**
1. В каждом брейкпоинте перекомпоновки — сначала обнулить углы, потом назначить внешние.
2. «Внешний» угол — на границе группы с фоном; внутренние стыки всегда прямые.
3. При изменении числа колонок на крупном тире (напр. 1920) — пересчитать, какие элементы становятся угловыми (`:nth-child`, при динамике — JS-классы).
4. Слитные «поля»: скругление — на контейнере, заливка-бейдж зеркалит угол дочерним `border-*-radius`.
5. Где логика на negative-margin бейджа (`.cta-discount`) — **не** прятать родителя `overflow: hidden`, это сломает перекрытие рамки.
6. Единый источник значений — `--radius-main` / `--radius-asym`; при fluid-скруглении сохранять принцип «внешний/внутренний».
7. **`--radius-*` тоже переводим в `rem`** → скругления масштабируются вместе с zoom (согласованно с 0.1). Бордюр `1px` при этом остаётся `px` (0.4).

### 5.3. Типографика: токены-роли → rem → Reflow/Zoom

> Порядок принципиален: **сначала зафиксировать токены из текущих значений (без визуальных изменений), затем менять механизм.** Иначе не понять, что сломалось — токены или масштаб.

3.1. **Инвентаризация.** Собрать все фиксированные `px` (шрифты, `padding/gap/margin`, размеры блоков, `--radius-*`) по компонентам. Источник — `docs/text-set.md` (уже есть таблица).

3.2. **Токены-роли (rem), без смены вида.** Определить роли и присвоить им **текущие отлаженные значения** (переведённые в `rem`):
   - Шрифт: `--fs-h1 … --fs-h4`, `--fs-body`, `--fs-small`, `--fs-label` (бывш. триггеры/капс-лейблы).
   - Размеры блоков: `--card-pad`, `--card-gap`, `--card-height`, `--radius-main`, `--radius-asym` и т.п.
   - Результат — **нулевой визуальный дифф** (чистый рефактор).

3.3. **Перевод размеров на `rem`.** Все значения из 3.1 → `rem`. Исключения — по 0.4. Проверка: при `html font-size: 16px` вид идентичен.

3.4. **Одна роль = один класс.** Убрать исключения, где один класс имеет два вида. Кейс: `.why-we-card .card-title` (капс-лейбл преимуществ) сейчас переопределяет `.card-title` — вынести лейбл в **отдельную роль-класс** (напр. `.card-label`) вместо контекстного оверрайда. Согласовать с a11y (см. 3.7).

3.5. **`clamp()` — только ≤1280.** Заголовки/ключевой текст — на `clamp()` с реперами (min/max), от `rem`-значений токенов. Выше 1280 `clamp` не для масштаба (0.3).

3.6. **Корень (Zoom) — крупные тиры.** `html { font-size: calc(100% * k) }` (a11y, 0.5):
   - база: `100%` (1×);
   - `@media (min-width: 1500px)` → `calc(100% * 1.08)`;
   - `@media (min-width: 1850px)` → `calc(100% * 1.3)`.
   Убрать `* var(--type-scale)` из значений (его роль выполняет корень). **Убедиться, что не остаётся второго уровня флюида** (0.6).

3.7. **a11y.** В блоке цен «Стоимость обработки» идёт `h2 → сразу h4` (пропущен `h3`) — либо добавить промежуточный `h3`, либо не перескакивать уровни.

3.8. **Отступы секций:** `padding: clamp(3rem, 6vw, 6rem) var(--gutter)` вместо жёстких `5rem 2rem`.

3.9. **Длина строк:** `max-width: ~65–75ch` для абзацев на широких экранах.

3.10. **Согласованные решения (реализация 3.2–3.3):**
   - Токены-роли — только 7 (`--fs-h1…h4`, `--fs-body`, `--fs-small`, `--fs-label`); применяем только при **точном** совпадении значения; размеры **не** консолидируем (ради пиксель-в-пиксель 1440).
   - `--fs-h1` — исключение: H1 остаётся `clamp()` (`28–34px` → `rem`), токен `2rem` — только для полосы `1025–1499`.
   - px-исключения: хайрлайны/`border-width`, `box-shadow`, `backdrop-filter: blur()`, `vh/vw`, `ch`, сами брейкпоинты. Всё геометрическое (отступы, размеры, `--radius`, `translate`, `letter-spacing` в `px`) → `rem`.
   - Инвентарь покрывает и `px` **внутри** медиазапросов (мобильные) — тоже → `rem` (ниже 1280 нулевой дифф).
   - Контейнер: единый `--container-max: 75rem`, пер-тировые `1360px/1536px` удаляем.
   - `--header-h: 80px → 5rem`; реальная высота шапки выводится из токена (все внутренние отступы — `rem`); `scroll-margin-top: 90px` (style.css:488) привязать к `--header-h`.
   - Вересковое поле `60px` — **пока оставляем `px`** (завязано на JS и `calc` в 498/949/1109/1152/1159); кандидат на §5.5.
   - Не удалять блок `@media (min-width:1850px)` целиком — там `.hero-title` clamp; в `@media (min-width:1500px)` только `:root`, его можно убрать.
   - Базовое `html { font-size: 100% }` (сейчас у `html` только `scroll-behavior`, style.css:165); в конце — `--type-scale` должно стать `0` вхождений.

### 5.4. Container queries (по компонентам)
4.1. CTA-бокс, «почему мы», price-card, b2b, отзывы — перекомпоновку перевести на `@container`.
4.2. **Обязательно** сохранить переключение углов на границе перекомпоновки контейнера.
4.3. Памятка: в `@container` единицы `cq*` не путать с `rem`-токенами; `cqw/cqi` — только там, где нужен масштаб от контейнера, а не от корня.

### 5.5. Крупноэкранная полировка (Zoom, 1920)
5.1. Hero: ширина ограничена, картинка масштабируется, разделитель на месте.
5.2. «Воздух» секциям и рост типографики обеспечиваются **корнем** (0.2/3.6), а не точечными правками.
5.3. **Контейнер — один `rem`.** Убрать пер-тировые `--container-max: 1360px/1536px` (style.css:989/996), оставить единый `--container-max: 75rem`. Тогда контейнер и шрифты растут одним множителем (корнем). **Следствие:** на ≥1500 контейнер станет `75rem × 1.08 = 1296px` (было 1360), на ≥1850 — `75rem × 1.3 = 1560px` (было 1536). База `1281–1499` = `75rem = 1200px` — **не меняется** (1440 пиксель-в-пиксель). Это осознанное изменение только на крупных тирах.
5.4. **Анимации:** проверить, что координаты — в `rem` или от геометрии (0.7). Именно тут проверяется, что zoom «встаёт».
5.5. Разобрать легаси-исключения `.hero-title` (`1025–1499` и clamp `32–38px` на ≥1850) и `geo-map height` — пересмотреть под новую модель. Внимание: при переводе clamp в `rem` его `px`-значения начнут расти вместе с корнем (на ≥1850 ×1.3) — потолок заголовка придётся пересчитать.

### 5.6. Регресс-тестирование и закрепление
6.1. Матрица разрешений: `390 / 520 / 768 / 1024 / 1280 / 1440 / 1500 / 1850 / 1920` (плюс высоты `720`, `1080`).
6.2. Чеклист по разделу «Фирменная логика скруглений» на каждом разрешении.
6.3. Проверка zoom: на `1500/1850` весь макет растёт пропорционально, ничего не «отваливается» из-за забытого `px`.
6.4. Закрепить в коде комментарий-контракт (§5.2.3).

### Риски / ограничения
- **Двойной флюид** (0.6): `clamp` + корень на одном свойстве = непредсказуемый размер. Контролировать.
- **a11y корня** (0.5): фиксированный `px` в `html font-size` запрещён.
- **Медиа-запросы в `rem`** не следуют за zoom → брейкпоинты только `px`.
- **Миграция `px`→`rem`** крупная: пропущенный `px` «отваливается» от общего масштаба → нужен инвентарь (3.1) и проверка на `1500/1850`.
- **`clamp()` требует реперов** (min/max), иначе «плавающие» размеры.
- **Анимации:** хардкод пиксельных координат ломается при zoom → переводить на `rem`/геометрию (0.7).
- **Крупный тир — только Zoom**, не перекомпоновка: число колонок сохраняется (иначе пересчитывать углы, см. раздел 4).
- **Исключение из унификации ширины:** локальные ограничения ширины внутренних текстовых элементов (`.calc-subtitle` `600px`, FAQ-ответ `820px`, отзывы `60ch`) — **не** разнобой контейнеров; на глобальный `--container-max` переводить **запрещено**. Унификации подлежат только внешние обёртки секций (`.hero-section`, `.calc-container`).
