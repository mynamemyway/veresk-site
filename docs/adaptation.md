## Как сейчас реализована адаптация (факты из кода)

**Подход:** desktop-first, почти все правила — `@media (max-width: …)`. Полностью отсутствует тир для больших экранов (нет ни одного `min-width` для ≥1400/≥1920).

**Брейкпоинты разрознены** (13+ разных): `1400, 1300, 1200, 1025, 1024, 768, 740, 720, 680, 600, 580, 520, 375`. Часть — точечные «заплатки» (580, 600, 720, 740), привязанные к конкретным компонентам, а не к системе.

**Контейнеров нет.** `.hero-section` и `.calc-section` — во всю ширину с `padding: 5rem 2rem`. Ограничение ширины — точечное, у кого как: `.calc-container` `max-width:1200px`, местами `820px`, `600px`, `60ch`. У **hero вообще нет `max-width`** → на 1920 он растягивается почти на всю ширину (~1856px), тогда как остальные блоки зажаты в 1200px.

**Сетки:** CSS Grid (`repeat(12, minmax(0,1fr))` в hero, `repeat(2/3/6…)` в остальных) + Flexbox. Технологии современные, это плюс.

**Типографика:** в основном фиксированные `px`. Fluid (`clamp`/`min`) — только hero-h1, футер, `geo-map height`, один текст B2B. Поэтому на 1920 шрифты выглядят мелко относительно макета.

**Прочее:** `rem` = 16px (font-size у `html` не задан); `box-sizing` глобальный; `:root` с CSS-переменными и темами (light/dark) — сделано хорошо; 1 container query (`@container 375px`); `viewport meta` корректная.

## Проблемы именно для 1920×1080

1. Выше ~1400px вёрстка просто «растягивается», а не адаптируется — нет верхней границы у hero.
2. Рассогласование: hero во всю ширь, остальное в 1200px → на 1920 разный ритм и вертикальная линия 58.33% уходит далеко от контента.
3. Фиксированные px-шрифты не масштабируются под большой макет.
4. Нет единой системы брейкпоинтов → любая правка под 1920 будет очередной «заплаткой».

## Рекомендации (современные стандарты, без кода)

1. **Не привязываться к «1920 как базовому».** Стандарт — контент-ориентированные брейкпоинты + ограничение ширины, а не подгонка под конкретный монитор. 1920 покрывается «крупным» тиром.
2. **Ввести единый контейнер** `.container` (или задать `max-width` для hero тоже): `max-width: 1280–1440px; margin-inline:auto; padding-inline: clamp(1rem, 4vw, 2.5rem)`. Тогда на 1920 контент центрируется с воздухом, а вертикальная линия/сетка остаются согласованными.
3. **Унифицировать брейкпоинты** до токен-набора: напр. `480 / 600 / 768 / 1024 / 1280 / 1500 / 1850`. Свести ad-hoc `580/600/680/720/740` к ближайшим.
4. **Добавить крупный тир** (`min-width: 1500px` / `1850px`): там увеличивать не «растяжением», а масштабом — шрифты, вертикальные отступы секций, размеры картинок.
5. **Fluid-типографика:** заголовки и базовый текст перевести на `clamp()` с потолком (напр. h1 `clamp(2rem, 1.2rem + 2vw, 3rem)`). Опционально — container units (`cqi`).
6. **Больше container queries** для компонентов (карточки, CTA-бокс, «почему мы») — меньше зависимость от вьюпорта.
7. **Fluid-отступы секций:** `padding: clamp(3rem, 6vw, 6rem) 2rem` вместо жёстких `5rem` — на 1920 не будет тесно.
8. **Сохранить то, что уже правильно:** токены `:root`, темы, `--radius-*`, grid. Их достаточно расширить, не переписывать.
9. **Ограничение длины строк** на широких экранах (`max-width: ~65–75ch` для абзацев) — иначе на 1920 текст тяжело читать.
10. **Вертикальный разделитель** (`.global-vertical-line` на 58.33%) связать с новым контейнером, иначе после ограничения ширины он «отвяжется».

**Практический план-минимум:** сначала ввести общий контейнер + крупный тир (1500/1850) и починить hero; затем — унификация брейкпоинтов и fluid-типографика; container queries — по мере рефакторинга компонентов.

## Фирменная логика скруглений при перекомпоновке (инвариант — не ломать)

> «Сохранить фирменную логику скругления углов при перекомпоновке объектов для разных разрешений: когда в стопку — меняются углы для скругления.» — Alex

**Суть паттерна.** Объекты, стоящие встык (тонкий стык 3px или общая рамка), читаются как **единый блок**. Скругляются только **внешние** углы группы (те, что граничат с фоном секции), внутренние стыки — **прямые**. Когда раскладка меняется (ряд → стопка, другая сетка), «внешними» становятся другие углы, и вёрстка **пересчитывает** скругления под новую геометрию. В каждом брейкпоинте перекомпоновки углы сначала **обнуляются** (`border-radius: 0`), затем назначаются заново — иначе правила прошлого тира наследуются каскадом.

**Где реализовано (карта для регресса):**

| Компонент | Раскладки и как меняются углы | Строки |
|---|---|---|
| Каталог `.pest-card` / `.pest-grid` | десктоп 6×1 (левый край первой, правый последней) → планшет 3×2 (4 внешних угла верх./ниж. ряда) → моб. 3 колонки; обнуление в каждом тире | 1840–1954 |
| Прайс `.price-card` / `.prices-grid` | 3×1, только внешние углы; логика снимается ≤1024 | 1143–1157 |
| Калькулятор `.v2-prices` / `.v2-calc` | пара карточек, внешние углы только ≥1025 | 1420–1430 |
| «Почему мы» `.why-we-step` / `.why-we-mark` | слитное поле; заливка-маркер зеркалит нижний правый угол (`border-bottom-right-radius`) | 2024–2049 |
| «Почему мы» `.why-we-card` | 2×2 → 1×4 (верх первой / низ последней) | 2338–2355 |
| Note-блок `.why-we-note-text` / `.why-we-note-actions` / `.why-we-note-tg` | в ряд: `12px 0 0 12px` + `0 0.75rem 0.75rem 0` + скос на tg `::before` → в колонку: текст `12px 12px 0 0`, монолит `0 0 12px 12px`, tg без скоса | 2198, 2214, 2253, 2301–2325 |
| B2B `.b2b-tag` / `.b2b-tags` | 2×3 (4 внешних угла) → в колонку (верх/низ) | 2497–2510, 2645–2669 |
| CTA hero `.cta-deal` / `.cta-discount` | слитная плашка; красный бейдж зеркалит угол и перекрывает рамку через negative-margin | 726, 747–749 |
| Hero-фото `.image-container-block` | асимметричное скругление `--radius-asym: 2rem 0.5rem 2rem 2rem` | 76, 628 |
| Отзывы `.review-card` / `.reviews-track` | внешние края ленты; управляются JS-классами `.is-edge-start/end` (до инициализации — `:first/last-child`) | 2986–3006 |
| Футер `.footer-grid` | внешние углы первого/последнего столбца; пересчёт в тирах | 1812–1849, 1934–1952 |

**Инварианты при адаптации под 1920 и рефакторинге:**
1. В каждом брейкпоинте перекомпоновки — сначала обнулить углы, потом назначить внешние.
2. «Внешний» угол — на границе группы с фоном; внутренние стыки всегда прямые.
3. При изменении числа колонок на крупном тире (напр. 1920) — пересчитать, какие элементы становятся угловыми (`:nth-child`, при динамике — JS-классы).
4. Слитные «поля»: скругление — на контейнере, заливка-бейдж зеркалит угол дочерним `border-*-radius`.
5. Где логика на negative-margin бейджа (`.cta-discount`) — **не** прятать родителя `overflow: hidden`, это сломает перекрытие рамки.
6. Единый источник значений — `--radius-main` / `--radius-asym`; при fluid-скруглении сохранять принцип «внешний/внутренний».

## Технический план реализации адаптации

### 0. Инварианты (что нельзя ломать)
- Фирменная логика скруглений (раздел выше) — на каждом тире пересчитывается, но принцип неизменен.
- Токены `:root`, темы light/dark, `--radius-*`, порядок каскада для углов.
- Вертикальный разделитель `.global-vertical-line` (58.33%) должен оставаться привязанным к контенту.
- `box-sizing: border-box`, `rem` = 16px, корректная `viewport meta`.

### 1. Каркас: единый контейнер + крупный тир
1.1. Задать глобальные токены контейнера (в `:root`):
   - `--container-max` (напр. `1320px`), `--gutter` (`clamp(1rem, 4vw, 2.5rem)`).
1.2. Применить контейнер к **hero** (сейчас без `max-width`) и согласовать с `.calc-container` — привести все секции к одному `max-width`/гуттеру (сейчас разнобой: 1200 / 820 / 600).
1.3. Связать `.global-vertical-line` с контейнером (позиционировать внутри общей обёртки, а не от вьюпорта).
1.4. Добавить тир `@media (min-width: 1500px)` и `(min-width: 1850px)`: масштаб не растяжением, а типографикой/отступами/размерами изображений.
1.5. Проверка: 1920 / 1440 / 1280 / 1080 — ритм, линия и ширина колонок совпадают.

### 2. Унификация брейкпоинтов
> **Статус: ВЫПОЛНЕНО.** Целевой набор `480 / 600 / 768 / 1024 / 1280 / 1500 / 1850` применён в `style.css`; все ad-hoc значения (`520/580/680/720/740/1200/1400/1440/681`) сведены методом rename-in-place (порядок каскада сохранён). JS-порог меню синхронизирован (`main.js`: `innerWidth > 1024`). Пары полос: `481–600`, `601–768`, `1025–1280`, `1025–1499`. Скобки сбалансированы.

2.1. Зафиксировать целевой набор (предложение): `480 / 600 / 768 / 1024 / 1280 / 1500 / 1850`.
2.2. Карта миграции существующих:

| Текущий брейкпоинт в коде | Целевой брейкпоинт в CSS | Метод переноса кода |
| :--- | :--- | :--- |
| `@media (max-width: 520px)` | `@media (max-width: 480px)` | Слить содержимое в общий блок 480px |
| `@media (max-width: 580px)` | `@media (max-width: 600px)` | Слить содержимое в общий блок 600px |
| `@media (max-width: 680px)` | `@media (max-width: 768px)` | Перенести внутрь блока 768px |
| `@media (max-width: 720px)` | `@media (max-width: 768px)` | Перенести внутрь блока 768px |
| `@media (max-width: 740px)` | `@media (max-width: 768px)` | Перенести внутрь блока 768px |
| `@media (max-width: 1025px)` | `@media (max-width: 1024px)` | Схлопнуть в единый блок 1024px |
| `@media (max-width: 1200px)` | `@media (max-width: 1280px)` | Слить содержимое в общий блок 1280px |
| `@media (max-width: 1400px)` | `@media (max-width: 1280px)` | Перенести внутрь блока 1280px |

| `@media (min-width: 1025px) and (max-width: 1440px)` | `@media (min-width: 1025px) and (max-width: 1499px)` | ⚠️ **НЕ переносить в 1280px.** Это защитная полоса `.hero-title` (32px): при схлопывании в 1280 на 1440 заголовок выпадет из неё и вырастет до базового `clamp` (34px). Верхнюю границу свести к тиру: `max-width: 1499px` (пара с `min-width: 1500`) |


2.3. Менять по одному, каждую границу проверять отдельно (регресс-риск у «заплаток»).
2.4. Ограничение: чистый CSS **не** поддерживает переменные в `@media`. Варианты — Sass/PostCSS-токены **или** комментарий-контракт со списком значений + дисциплина.

```css
/* ==========================================================================
   КОНТРАКТ АДАПТИВНОСТИ (СИСТЕМНЫЕ БРЕЙКПОИНТЫ)
   ========================================================================== 
   @media (max-width: 1280px) -> Ноутбуки / Мелкий десктоп
   @media (max-width: 1024px) -> Планшеты (горизонтальные)
   @media (max-width: 768px)  -> Планшеты (вертикальные) / Крупные мобильные
   @media (max-width: 600px)  -> Мобильные (горизонтальные)
   @media (max-width: 480px)  -> Смартфоны (вертикальные)
   
   @media (min-width: 1500px) -> Большие мониторы / Ноутбуки 15.6" (скейлинг тир-1)
   @media (min-width: 1850px) -> Крупный тир (Full HD масштаб / 4K)
   ========================================================================== */
```

  Как безопасно провести эту чистку (Алгоритм):
  
  Не удаляй код старых брейкпоинтов.
  1. Создай внизу файла секцию @media (max-width: 768px).
  2. Перенеси туда всё содержимое из старых @media (max-width: 740px), 720px и 680px.
  3. Сами пустые скобки старых медиа-запросов удали.
  4. Повтори это для остальных групп по таблице выше.

### 3. Fluid-типографика и отступы
3.1. Инвентаризировать фиксированные `px`-размеры (h1/h2/h3, тексты, кнопки).
3.2. Перевести заголовки и ключевой текст на `clamp()` с потолком; базовый `body` — от `rem`.
3.3. Отступы секций: `padding: clamp(3rem, 6vw, 6rem) var(--gutter)` вместо жёстких `5rem 2rem`.
3.4. Ограничить длину строк абзацев (`~65–75ch`) на широких экранах.

### 4. Container queries (по компонентам)
4.1. CTA-бокс, «почему мы», price-card, b2b, отзывы — перекомпоновку перевести на `@container` (сейчас только один `@container 375px`).
4.2. **Обязательно** сохранить переключение углов на границе перекомпоновки контейнера.

### 5. Крупноэкранная полировка (1920)
5.1. Hero: ширина ограничена, картинка масштабируется, разделитель на месте.
5.2. Добавить «воздух» секциям, увеличить типографику крупного тира.
5.3. Проверить сетки на добавление/перераспределение колонок и пересчёт углов.

### 6. Регресс-тестирование и закрепление
6.1. Матрица разрешений: `390 / 520 / 768 / 1024 / 1280 / 1440 / 1920` (плюс высоты `720`, `1080`).
6.2. Чеклист по разделу «Фирменная логика скруглений» на каждом разрешении.
6.3. Зафиксировать в коде комментарий-контракт с набором брейкпоинтов.

### Риски / ограничения
- Переменные в `@media` — только через препроцессор (иначе дисциплина + комментарий).
- `clamp()` требует реперных макетов (min/max), иначе «плавающие» размеры.
- Сдвиг брейкпоинтов = регресс-риск: проверять границы отдельно.
- Крупный тир не должен превращаться в «растяжение»: только масштаб, не ширина контента.
- **Исключение из унификации брейкпоинтов:** защитная полоса заголовка hero `@media (min-width: 1025px) and (max-width: 1440px)` (`.hero-title` = 32px) **не** схлопывается в 1280px — иначе на 1440 заголовок выпадет из полосы и вырастет по базовому `clamp` до 34px. Верхнюю границу сводить к тиру: `max-width: 1499px` (пара с `min-width: 1500`).
- **Исключение из унификации ширины:** локальные ограничения ширины внутренних текстовых элементов (`.calc-subtitle` `600px`, FAQ-ответ `820px`, отзывы `60ch`) — это **не** разнобой контейнеров. Переводить их на глобальный `--container-max` **запрещено**. Унификации подлежат только внешние обёртки секций (`.hero-section`, `.calc-container`).

### Файлы к изменению
- `assets/css/style.css` — основной.
- `index.html` — обёртки-контейнеры (hero) при необходимости, обёртки под `container-type`.
- опционально `assets/css/tokens.css` — вынести брейкпоинт-контракт и токены.
